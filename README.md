# SCI-Sensor-MDPI

사족보행 로봇(Unitree Go2, Hesai XT16 라이다, RealSense RGB-D, 팬틸트 카메라)이 몇 층인지 모르는 상태에서 안내도 위 자기 위치를 찾고, 위치가 애매할 때만 멈춰 호실 번호판을 보게 하는 연구의 코드와 실험 정리다.

## 폴더

| 폴더 | 내용 |
|---|---|
| `floor_id/` | 위치추정 패키지. 라이다 구조점과 오돔을 층별 안내도에 맞춰 위치·방향·축척 후보와 층 순위를 낸다(`floor_id.py` 층 판별, `localizer/rt_localizer.py` 실시간 위치추정, `localizer/metric_fit_v2.py` 후보 정밀 검증, `maps/` 세 건물 지도) |
| `E2_초기위치/` | 제자리 관측 한 번으로 모든 층·칸·방향·축척 후보 중 Top-100 뽑기 |
| `E3_걸으며좁히기/` | 15·30·45·60초 걸으며 후보 좁히기. `지도8차_평가/` 는 8차 지도로 E2·E3 를 다시 돌리고 평가·그림을 만든 코드(벽 반대편 통과 판정 포함) |
| `E4_표지판호출/` | 매 시점 위치 상태 판단과, 모호할 때만 표지판 앞에서 멈추기(녹화본 실험) |
| `이벤트_실시간/` | 로봇에서 도는 표지판 멈춤·팬틸트 조준 코드(2026-10-09 판) |

실험 폴더마다 `README.md` 는 파일별 역할과 실행 순서, `실험정리.md` 는 방법·결과·남은 문제다. 실험 코드는 `floor_id` 를 고치지 않고 불러 쓴다.

## 지금까지 결과

모든 실험은 같은 65개 출발점(정보관 1~9층, 공학관 1·2층, 소융대 1·6층의 13개 층 × 장소 종류 5곳)을 쓴다. 정답(층, 3 m, 30°)은 채점에만 쓰고 후보 계산이나 멈춤 판단에는 넣지 않았다. 아래 숫자는 정보관 계단 앞과 9층 복도 방화셔터를 지나갈 수 있게 고친 8차 지도로 다시 돌린 결과다.

E2 에서는 서서 한 번 본 라이다로 정답 위치가 Top-100 안에 드는 출발점이 31곳(48%), 1위가 맞는 곳이 6곳이었다. 정답 층은 Top-100 안에 63곳 들어 있으니, 남은 차이는 대부분 축척과 층 안 위치다.

E3 에서는 E2 후보를 이어받고 15초마다 위치추정 노드가 층마다 새로 찾은 후보를 합쳤다. 1위가 맞는 출발점은 15·30·45·60초에 14·21·27·23곳이고, 후보 안에 정답이 있는 곳은 42·47·52·52곳이다. 1위가 틀린 이유를 나눠 보면 정답 후보를 찾고도 1위가 다른 층인 경우가 시점마다 25~29곳으로 가장 많고, 같은 층 안에서 자리를 틀린 경우는 45초부터 없다. 라이다 기하는 층 안 위치는 잘 찾지만 몇 층인지는 잘 가르지 못한다.

E4 의 위치 상태 판단은 "그 시점 1위가 틀린 순간"을 모호해야 할 순간으로 볼 때 정밀도 76%, 재현율 99%(F1 0.86)이고, 틀렸는데 확정이라고 한 경우는 0.6% 다. 멈춘 곳 중 진짜 표지판은 절반쯤(50%)이다. 60초 안에 진짜 번호판 앞에 선 출발점은 43곳이고, 그 번호로 층을 정하면 60초 뒤 위치가 맞는 곳이 23곳에서 42곳으로 는다(처음부터 층을 알면 48곳). 번호판 하나를 읽은 뒤 같은 층 후보끼리만 비교하면 확정 선언이 12% 에서 49% 로, 1위 정답이 29% 에서 61% 로 오른다(판독이 늘 맞는다고 친 상한).

로봇 실시간 노드에 새로 넣은 "벽을 반대편으로 넘은 층은 뒤로" 판정을 같은 65곳 후보에 붙여 봐도 1위 정답과 후보 안 정답 숫자는 바뀌지 않았다. 녹화 뒤 보정한 오돔이라 얇은 벽을 넘는 후보가 1위 근처에 거의 오지 않기 때문이다.

## 남은 문제

번호판을 읽어 층을 정한 뒤에도 그 층 후보 안에 정답 자리가 없는 경우가 35% 다. 읽은 호실 문 앞에 후보를 새로 넣는 재탐색이 다음 개선점이다. 정보관 3층 복도 양 끝에서 오돔이 실제보다 1.5~2 m 짧게 나와 데이터셋 쪽에 확인을 요청했다. 공학관 지도는 방 안 잔여물을 문으로 본 곳이 많아 지도 생성 규칙을 고쳐 다시 만드는 편이 좋다. 실험 오돔은 녹화 뒤 보정한 판이라, 현장 성능은 로봇 실시간 시험으로 따로 확인해야 한다.

다음은 로봇 실시간 쪽이다. 실시간 위치추정 기록을 이벤트 실행기(`--loc-url`)에 붙여 멈춤 → 조준 → 촬영 → 번호 판독을 현장에서 시험한다.

## 돌리려면

층별 데이터셋(A1.3.1 구조점·오돔·RGB-D 녹화, 채점용 정답)은 용량 때문에 넣지 않았다. 코드에 적힌 데이터 경로(`/data…`, `/data2…`)는 각자 환경에 맞게 바꿔야 하고, 실험 코드는 위치추정 패키지를 `/data/kci_work/floor_id_pkg/floor_id` 경로로 부른다.

파이썬 3.10 에서 numpy, scipy, opencv, matplotlib 으로 돌렸다. 이미지 모델(SigLIP base-patch16-224, Qwen3-VL-2B-Instruct)은 torch·transformers 가 든 별도 환경에서 불렀다. 위치추정은 CuPy 가 있으면 GPU 로 도는데 결과는 CPU 와 같다. 결과 그림과 표 전체는 따로 전달한 정리본(zip)에 있다.

## 갱신 기록

2026-10-12 처음 올림. 위치추정 패키지, E2·E3·E4 실험 코드와 정리, 로봇 이벤트 코드(2026-10-09 판).

2026-10-13 지도 8차로 최신화. `floor_id/maps/` 의 문 마스크 24장을 실험과 로봇이 쓰는 판으로 바꿨다. 정보관 계단 앞 방화셔터(3·5·6·7·8·9층)와 9층 복도 셔터를 지나갈 수 있는 곳으로 넣었고, 셔터는 "계단 가까이에서 계단 긴 변과 나란하고 길이가 그 0.6배 이상이며 방과 붙지 않은 직선 벽선"이라는 규칙으로 찾았다(만든 코드 `E3_걸으며좁히기/지도8차_평가/make_stairfix_maps.py`, 사람 확인 한 곳은 `apply_map_review.py`). 이 지도로 E2·E3·E4 를 다시 돌려 각 폴더의 `실험정리.md` 와 위 결과 숫자를 바꿨다. 새로 넣은 코드는 8차 지도 평가(`e2e3_eval_v8.py`), 논문용 그림(`e3_paper_figs.py`, `e2_floor_maps_big.py`), 벽 반대편 통과 판정(`wall_pass_test.py`, `e3_wallpass_post.py`, `e3_wallpass_eval.py`), 번호판을 읽은 뒤 판단 흉내(`E4_표지판호출/e4_read_loop.py`)다. 기존 스크립트는 지도·결과 폴더를 고르는 환경변수를 더했고 기본값은 그대로다.
