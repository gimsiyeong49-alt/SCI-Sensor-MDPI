# SCI-Sensor-MDPI 실험 코드

사족보행 로봇(Unitree Go2, Hesai 라이다, RealSense RGB-D)이 층·건물을 모르는 상태에서 안내도 위 위치를 찾는 실험의 코드다. 실험마다 폴더 하나이고, 폴더 안 `README.md` 에 파일별 역할과 실행 순서를 적었다.

| 폴더 | 실험 |
|---|---|
| `E2_초기위치` | 제자리 관측 한 번으로 모든 층·칸·방향·축척 후보에서 Top-100 을 뽑는다(출발점 65곳). |
| `E3_걸으며좁히기` | 15·30·45·60초 걸으면서 후보를 좁힌다. 최종안은 E2 후보를 이어받고 위치추정 노드의 층별 재탐색 후보를 15초마다 합친다. |
| `E4_표지판호출` | 매 시점 위치 상태(확정, 층 간 모호, 층 내 모호, 관측 부족, 센서 이상)를 판단하고, 모호할 때만 멈춰 표지판·호실 번호판을 보게 한다. 오돔 튐 검출과 층을 아는 경우의 이벤트 재실행도 여기에 있다. |

## 그대로 돌리려면

이 저장소에는 실험에서 새로 짠 스크립트만 있다. 위치추정 자체는 협업자의 `floor_id` 패키지(`floor_id.py`, `rt_localizer.py`, `metric_fit_v2.py` 등)를 고치지 않고 불러 썼는데, 그 패키지와 층별 데이터셋(A1.3.1 구조점·오돔·RGB-D 녹화, 채점용 정답), 안내도 지도는 들어 있지 않다. 코드에 적힌 데이터 경로(`/data…`, `/data2…`)는 각자 환경에 맞게 바꿔야 한다.

파이썬 3.10 에서 numpy, scipy, opencv, matplotlib 으로 돌렸다. 이미지 모델(SigLIP base-patch16-224, Qwen3-VL-2B-Instruct)을 쓰는 스크립트는 torch·transformers 가 든 별도 환경에서 불렀다. E3 의 노드 계산은 협업자 패키지가 CuPy 를 찾으면 GPU 로 도는데, 결과는 CPU 와 같다.

정답은 채점에만 쓰고 후보 계산·멈춤 판단에는 넣지 않았다. 결과 표와 그림은 용량 때문에 이 저장소에 넣지 않고 따로 전달한 정리본에 있다.
