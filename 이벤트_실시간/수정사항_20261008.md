## 꼭 알아야 하는 것

### 1. 계단 숫자 정정

10-06 README 에 "계단 관측 36번 중 31번 맞음"이라고 적었는데 옮겨 적다 틀렸습니다. 최종 설정 실제값은 35번 중 30번(86%)입니다. 맞은 비율은 거의 같고 코드와는 상관없습니다.

### 2. 멈춤 규칙 (10-07)

10-06 판은 "장소가 애매하거나, 1위가 크게 튀면서 후보가 흩어질 때" 멈췄습니다. 지금은 "장소가 애매하고 오돔·센서가 정상일 때"만 멈춥니다(`live_event_runner.py --stop-rule amb_sensor_ok`, 기본값). 오돔이 튀어서 위치추정이 흔들린 것을 장소가 헷갈리는 것으로 착각해 멈추지 않게 하려는 것입니다. 옛 규칙은 `--stop-rule amb_or_jump` 로 쓸 수 있습니다. 녹화본 13개 층에서는 두 규칙의 멈춤이 같았습니다(4층·8층 확인).

### 3. 오돔 튐 판단과 고치기 (10-08, 새 파일 `code/sensor_check.py`)

4층 오돔 사본에 일부러 튐 8개(0.5~3 m 순간이동, 10~45° 순간 회전)를 넣어 시험했더니 10-07 의 판단(1초 동안 속도 2 m/s, 회전 120°/s 초과)은 3개만 잡았습니다. 작은 튐은 '장소가 헷갈림'으로 착각해 멈춤까지 허용했고, 튐 뒤 위치추정이 1위 3 m 안 77% → 40% 로 무너졌습니다.

그래서 판단을 셋으로 바꿨습니다.

| 판단 | 기준 | 근거 |
|---|---|---|
| 오돔 한 걸음(0.1 s) | 속도 > 3.0 m/s 또는 회전 > 150°/s | 13개 층 정상 주행 최대 2.3 m/s, 104°/s |
| 자이로와 회전 맞춤 | 0.3 s 동안 오돔 회전 − 자이로 적분(앞 30 s 중앙값으로 바이어스 뺌) > 9° | 13개 층 정상 최대 7.1° |
| 오돔 끊김 | 다음 자세까지 > 1.0 s | |

자이로는 `/utlidar/imu` 를 씁니다. 축·부호·시각 차이는 처음 60초로 정하고, 축이 확실하지 않으면(상관 0.5 미만이거나 다른 축의 2배가 안 되면) 120초, 180초에 다시 맞춥니다. 녹화본 13개 층 모두 z 축, 부호 −, 시각 차이 0~0.14 s 로 같게 나왔습니다.

튐을 잡으면 그 한 걸음만 "직전 걸음의 몸체 기준 이동 + 자이로 회전"으로 바꾸고 그 뒤 궤적은 그대로 이어 붙입니다. 위치추정 창을 튐에서 끊는 방법도 시험했는데 1위 3 m 안이 23% 로 더 나빠져서 쓰지 않습니다.

| 4층 튐 8개 | 고치기 전 | 고친 뒤 | 튐 없는 원래 |
|---|---|---|---|
| 튐 감지 | 3/8 | 8/8 | |
| 센서 오류를 '헷갈림'으로 착각한 초 | 101 | 52 | |
| 1위 3 m 안 (60초 이후) | 40% | 72% | 77% |

정상 녹화본 13개 층에서는 순간 이동·회전·자이로 불일치로 잘못 잡은 것이 0건입니다. 잡힌 것은 실제로 오돔이 1초 넘게 빈 곳 6곳(4층 3곳, 5층·9층·공학관 1층 1곳씩)뿐이고, 그 순간 멈춘 적이 없어 이벤트 결과는 바뀌지 않습니다.

## 협업자 쪽에서 해 줄 것

로봇에서 쓰려면 FAST-LIO 자세가 위치추정에 들어가기 전에 `OdomGuard` 를 거쳐야 합니다. 위치추정 코드는 건드리지 않았습니다.

```python
from sensor_check import OdomGuard
g = OdomGuard()
# /utlidar/imu 가 올 때마다 (자이로 축 순서 그대로)
g.add_gyro(t_sec, gx, gy, gz)
# FAST-LIO 자세를 odom_link 규약(x := −x, yaw := −yaw)으로 바꾼 뒤
for t, x, y, yaw, fixed in g.add_pose(t_sec, x, y, yaw):
    ...   # 이 자세를 위치추정에 넣는다. fixed 가 True 면 튐을 고친 걸음
```

`add_pose` 는 0.4초 늦게 판단이 끝난 자세부터 돌려줍니다(자이로 0.3 s 창 때문). 노트북에서 자세 하나에 11~14 ms 였고, 일괄 처리(`sensor_check.py --repair-to`)와 결과가 같습니다. Orin 시간은 재지 않았습니다.

이벤트 쪽에 알려 주려면 `--loc-url` 이 돌려주는 1초 기록에 `"sensor_bad": true` 를 넣으면 그 초는 멈추지 않습니다. 그 초 안에 `fixed` 가 True 인 걸음이 있었으면 true 로 보내면 됩니다. 없는 키는 false 로 봅니다.
