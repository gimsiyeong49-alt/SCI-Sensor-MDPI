# E4 애매할 때 멈춰서 표지판 보기 정리 (2026-10-12 갱신)

> **본 결과는 [1_본결과_층모름/](1_본결과_층모름/) 과 [2_본결과_상태판단/](2_본결과_상태판단/) 이다(2026-10-12).** 층을 알려 주지 않고 65개 출발점에서, E3 최종 방법인 합치기 후보(E2 Top-100 + 15초마다 노드 재탐색)로 잰 결과다.
>
> - 상태 판단: 다층 판단은 모호성 탐지 F1 0.86, 잘못된 확신 0.6% (단일 층 판단은 F1 0.63, 잘못된 확신 35%). "위치 확정"일 때 1위가 맞는 비율 96%.

> 모호함 기준은 2026-10-11 다시 세웠다([모호함_판단기준.md](모호함_판단기준.md)). 아래 나머지 내용(배포판 C, 13개 층 전체 주행)은 **정답 층을 알려 준 상태**에서 표지판 검출과 활용을 따로 확인한 보조 검증이다. 새 모호함 기준으로 같은 조건을 다시 돌려도 결과는 C 와 같았다(모호함 문서 6절).

## 지금 알고리즘 (배포판 C, 2026-10-09)

코드 하나(`scripts/live_event_runner.py`)가 녹화 실험과 로봇 실시간에 같이 쓰이고, 아래가 기본값이다. 로봇에는 `~/kci_event_handoff_20261009/` 로 넣었다(파일 73개 md5 일치).

1. 위치추정: 협업자 위치추정 패키지(RTLocalizer), 지난 60초 라이다. 지도 축척·방향은 걸으면서 30초마다 추정한다(고정 축척 안 씀).
2. 매 초 상태를 넷으로 나눈다. 확실, 헷갈림(1위와 5 m 밖 후보의 점수 차 ≤ 1.5), 헷갈림 + 긴 직선 복도(벽 방향이 한쪽뿐), 센서 이상(`sensor_check.py`: 0.1초 걸음 3 m/s·150°/s 초과, 0.3초 자이로 불일치 9° 초과, 1초 넘는 끊김).
3. 멈춤은 헷갈리면서 센서가 정상일 때만 허용한다(`amb_sensor_ok`). 확실할 때는 3초에 한 장만 처리한다.
4. 후보: 1초에 2장, 작은 덩어리를 뽑아 지난 장면 것과 이어 붙이고 깊이 7 m 안 벽 구간(장면당 최대 8개)으로 묶는다.
5. SigLIP 문구 세 개의 최댓값: "a small room name plate", "a small room name plate near a door", "a hallway sign perpendicular to the wall".
6. 거르기: 실제 폭 0.85 m 초과, 바닥 기준 높이 0.6~2.8 m 밖, 게시판처럼 보이는 것은 뺀다. 점수는 지금까지 본 구간의 상위 10% 선을 넘고 이번 장면 점수가 0.078 이상이어야 한다.
7. 멈출 자리: 아직 안 본 벽 자리(0.7 m 칸) 중 1등. 벽 자리 점수는 **최근 3번 관측 평균**이다(C 에서 바뀜, 아래 갈래 참고).
8. 같은 표지판 다시 멈추기 막기: 이미 멈춘 3D 자리에서 2 m 안이면서 최근 60초 안이면 안 멈춘다(C 에서 추가).
9. 계단: 의미지도상 계단이 보일 만하면 Qwen3-VL 2B 에 RealSense 화면을 물어 5 m 안이면 '계단 관측'으로 기록한다. 글자를 읽을 필요가 없어 멈추지 않는다. 엘리베이터는 끈다.

옛 동작(A)은 `--spot-recent 0 --ask-same-m 0 --ask-same-sec 0` 으로 돌릴 수 있다.

## 요약

- 헷갈릴 때만 멈추면 보이는 대로 다 멈출 때보다 멈춤이 28% 적은데(445 → 321번), 번호를 읽었을 때의 위치추정 효과는 오히려 조금 높다(1위 3 m 안 81.6 → 83.5%). 확실할 때의 멈춤은 쓸모가 없었다.
- 배포판 C 는 10-08 판(A)보다 멈춤이 적고(343 → 321), 같은 자리 재멈춤이 18 → 6% 로 줄었으며, 판정 층에서 본 호실이 20 → 25개(57개 중)로 늘었다. 정밀도(멈춘 것 중 진짜 표지판)는 57.5 → 58.1% 로 비슷하다.
- 멈춘 것 중 진짜 표지판은 58%(판정 74개 중 43개)다. 틀린 31개는 상자·기계, 다른 표지·글씨, 종이·안내문이 대부분이다.
- 판정 층에서 지나간 호실 57개 중 25개(44%)를 봤다. 놓친 87개의 45% 는 헷갈렸는데 후보를 못 찾은 경우, 28% 는 확실해서 규칙상 안 멈춘 경우, 24% 는 다른 곳에 멈춰 있던 경우다.
- 표지판을 볼 확률(지나간 호실 중 멈춰서 본 호실): 13개 층 합계 64%(156/243, 판정 안 한 층은 상한), 층별 평균 56%(호실이 2~3개뿐인 2층·소융대 1층 빼면 66%). 사람이 판정한 4개 층만 엄격하게 세면 44%(25/57).
- 계단 관측은 36번 중 30번(83%) 맞았다.
- 오돔 튐 판단을 고쳐 일부러 넣은 튐 8개를 모두 잡고(3 → 8개), 튐 뒤 위치추정 1위 3 m 안이 40 → 72% 로 회복됐다(튐이 없을 때 77%). 정상 13개 층 오경보는 0이다.
- 처리 시간은 개발 노트북에서 장면당 중앙 162 ms 다. 로봇(Orin) 시간은 아직 재지 않았다.

## 실험 방법

### 데이터

13개 층 녹화본(위치추정 구간 104.7분, 오돔 이동 2,868 m)을 실시간과 같은 코드로 재생해 돌렸다. RGB 는 RealSense 640×480 이라 번호 글자는 못 읽는다. 그래서 "번호를 읽었다면"은 시뮬레이션으로 낸다.

### 채점

정밀도는 사람이 멈춘 상자를 전부 판정한 4개 층(2·7층, 공학관 1층, 소융대 1층)만 쓴다. 판정 층에서 C 의 미판정 멈춤은 0개다.

본 호실(호실 단위 재현율)은 의미지도와 채점용 정답 경로로 자동 계산한다. 분모는 호실 벽 중 복도 쪽이 실제 경로 3 m 안으로 지나간 호실이고, 분자는 멈춘 3D 점을 정답 자세로 지도에 찍었을 때 호실 벽 1.5 m 안에 든 호실이다. 판정 층은 사람이 표지판이라고 한 멈춤만 센다. 판정 안 한 층은 틀린 멈춤도 세게 되어 상한이다.

"번호를 읽었다면"은 멈춘 곳에서 가장 가까운 호실 번호를 정답으로 읽었다고 치고 위치추정에 넣어 본 상한이다(`obs_feedback.py --oracle-numbers --dedup-num`). 60초 안 같은 번호는 한 번만 센다. 결과는 매 초 1위 후보가 실제 위치 3 m 안인 비율, 그리고 확신하면서 틀린 비율로 낸다.

### 갈래: A → B → C

A(10-08) 의 멈춤 중 같은 호실 재멈춤이 133번이었고 그중 82번이 10초 안(같은 표지판에 다가가며 또 멈춤), 26번이 60초 넘어 돌아오며 다시 보기였다. 2 m 만 막으면 돌아오며 다시 보는 것까지 막혀 4층 번호판이 4 → 3 으로 줄어서, 최근 60초만 막는 B 로 했다.

6층·8층에서 표지판이 보이는데 못 잡던 원인은 벽 자리 점수 평균이었다. 긴 복도에서 표지판이 멀리서 작게 보일 때의 낮은 점수가 수십 번 쌓여, 바로 앞에서 0.11~0.12 가 나와도 평균이 기준(0.09) 밑으로 끌려 내려갔다(6층 헷갈리는 동안 놓친 13호실 중 10, 8층 8 중 5). 그래서 최근 N번만 평균하게 했다. 모든 층 같은 규칙이다. N 을 바꿔 13개 층을 돌리고 새 멈춤은 사용자가 전부 판정했다.

| | A | 최근 2번 + B | **C: 최근 3번 + B** | 최근 5번 + B |
|---|---|---|---|---|
| 표지판 멈춤 | 343 | 394 | 321 | 274 |
| 정밀도(판정 층) | 57.5% | 50.5% | 58.1% | 55.6% |
| 판정 층 본 호실(57개 중) | 20 | 29 | 25 | 19 |
| 6층 본 호실(21개 중, 상한) | 7 | 18 | 15 | 12 |
| 번호 읽었다면 1위 3 m 안 | 81.3% | 84.4% | 83.5% | 82.0% |

N 이 작을수록 더 많이 멈추고 더 많이 보며, 클수록 A 에 가까워진다. 값이 고르게 변해 3 이 우연히 맞은 값은 아니다.
