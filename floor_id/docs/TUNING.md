# 손대도 되는 것과 안 되는 것

## 절대 규칙 (프로젝트 최우선 제약)

1. **층별 조건문·하드코딩 금지.** 건물마다 다른 점은 `config/buildings.yaml` 에만 쓴다.
   이 시스템의 최우선 목표는 처음 보는 안내도로의 일반화다.
2. **성적을 인용할 때는 설정을 함께 적는다.** 창 길이 하나로 오차가 43.78m ↔ 2.52m 로 갈린 적이 있다.
3. **눈으로 확인하기 전에는 "됐다"고 하지 않는다.** 수치만 보고 판단해서 틀린 적이 여러 번 있다.

## `config/buildings.yaml`

| 항목 | 바꿔도 되나 | 설명 |
|---|---|---|
| `buildings.*` | **예** | 건물 추가·지도 경로·층 수. 새 건물은 여기만 늘리면 된다 |
| `buildings.*.scale` | **예** | 층별 안내도 해상도가 1.5배 넘게 차이나면 `per_map` |
| `scene_source` | 아니오 | `lidar` 고정. `depth` 로 되돌리면 깊이 토픽이 필요해진다 |
| `consts.window_s` | 신중히 | 창 길이. 바꾸면 아래 성적표가 무효 |
| `consts.scene_side_near_m` | **아니오** | `0`(제한 없음)이 최선이다. 제한하면 성능이 떨어진다 |

### `scene_side_near_m` 이 0 이어야 하는 이유

LiDAR 로 장면(복도/교차로/막다른길)을 판단할 때 옆 거리를 몇 m 안쪽만 볼지 정하는 값이다.
깊이 카메라 라벨을 잘 흉내내려고 9m 로 제한했더니 **라벨 일치율은 최고(82.3%)인데 실제 성적이 가장 나빴다.**

| 옆 거리 한도 | 4F 위치추정 중앙 오차 | 3m 이내 |
|---|---|---|
| 8 m | 1.25 m | 82% |
| 10~11 m | 0.99 m | 85% |
| **12 m 이상 · 무제한** | **0.62 m** | **88%** |

12·13·14·16·20·무제한이 전부 같은 값이다. 12가 최적점인 게 아니라 **제한 자체가 해로웠다.**
라벨을 흉내내는 것이 목표가 아니라는 실측 근거다. 중간 지표로 튜닝하지 말 것.

## 성적을 다시 재는 법

설정을 바꿨으면 오프라인 데이터로 다시 재고, 바꾼 설정을 함께 적는다.

```bash
tools/ab_scene_compare.py 기존=out/a 새설정=out/b     # 구간별 판정·순위 비교
tools/ab_scene_summary.py                              # 세 건물 한 표로
```

## 알고리즘을 건드려야 한다면

`localizer/` 는 오프라인 연구 저장소(`/home/user/semloc_ws`)에서 그대로 복사한 것이다.
고칠 일이 생기면 연구 저장소에서 고치고 24장·100구간 회귀를 돌린 뒤 다시 복사한다.
여기서 직접 고치면 두 벌이 갈라진다.
