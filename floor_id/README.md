# 온보드 층 판별 패키지 (2026-09-30, 10-01 갱신)

안내도로 만든 지도 위에 누적 LiDAR 를 끼워 **지금 몇 층인지** 맞힌다.
정보관(9층)·공대(7층)·소융대(8층) 지도가 들어 있고, **깊이 카메라를 쓰지 않는다.**

```bash
python3 floor_id.py --building sw --data /경로/주행데이터
```

## 한눈에

```
floor_id.py            진입점. 이것만 실행한다
config/buildings.yaml  건물 3개 설정 — 새 건물은 여기만 늘린다
localizer/             알고리즘 18개 모듈       192 KB
maps/                  세 건물 24개 층 지도     9.1 MB
tools/                 검증·비교 도구(온보드 실행에는 불필요)
```

- 필요: Python 3.10 + `numpy scipy opencv-contrib-python pyyaml pillow`. **GPU·ROS 불필요.**
- 지도가 패키지 안에 있어 **경로를 고칠 필요가 없다.**
- 속도: 구간 하나당 (지도 수 × 8~25초). 9층이면 한 구간에 2~3분.

## 성적 (오프라인 실측, 세 건물 100구간)

정답 **1위 21% · 상위3 45%** (무작위 1위 12% · 상위3 40%). 설정: 창 60초 · 장면 lidar(옆 거리 제한 없음) · 소융대 per_map 축척.
깊이 카메라를 쓰던 기존 구성(1위 21 · 상위3 46, 09-29 지도)과 사실상 같다.
10-01 소융대 지도 교체로 소융대 10구간이 상위3 6→5(1위 2 그대로), 10-05 저녁 방 모양·화장실 반영으로 5→4(아래 변경 이력). 바뀐 구간(S6 70초)은 복도만 보이는 구간이라
문틀 끝 몇 픽셀 차이로 복도 위 다른 지점이 이긴 것이다 — 지도 품질 문제가 아니라 복도 구간의 원래 불안정성.

> 한 구간만 보고 층을 확정하지 말 것. 여러 구간을 모아 다수결로 쓸 것.

## 이 패키지가 하지 않는 것

- **ROS 노드가 아니다.** 폴더에 저장된 주행 데이터를 읽어 오프라인으로 돈다.
  실시간 토픽 구독은 로봇 쪽에서 이 형식으로 모아 주면 된다(형식은 USAGE §2).
- **미터 축척이 검증되지 않았다.** 안내도에서 추정한 값이라 실측 handshake 전까지 m 단위 결과를 그대로 쓰지 말 것.
- **MCL 마스크는 층 판별이 쓴다**(`maps/*_semmaps/<n>F/mcl/`). 후보 자리 = 자유공간 ∩ 건물 안(`building_footprint`)
  − `no_go`·화장실·계단, 축척·방향마다 점수 상위 3개(top-k=3)를 국소 정합하고, 건물 밖으로 나간 점은 `building_footprint` 로 감점한다.
  화장실·계단 마스크는 `sem/` 에서 읽는다. LiDAR 팀 MCL 노드용 13개 레이어 묶음(`/home/user/mcl_interface_ws/output/`)은 이 패키지에 없다.

## 출처

알고리즘 원본은 연구 저장소 `/home/user/semloc_ws`, 지도 생성 절차는 `HANDOFF_FLOORPLAN_ALL_20260921.md`.
고칠 일이 생기면 연구 저장소에서 고치고 회귀를 돌린 뒤 다시 복사한다(TUNING.md 참고).

**지도 갱신**
- 로봇에서: 옆의 지도 생성 패키지로 만든 결과를 복사한다.
  ```bash
  cp -r ../map_gen/out/sw/floor_id_maps/* maps/     # sw_maps_perfloor · sw_semmaps (축척 yaml 포함)
  ```
- 노트북(연구 저장소)에서: `tools/sync_maps.sh [건물]` — 연구 저장소의 지도 링크를 따라가 실물로 복사한다.

정보관·공대의 지금 지도는 정리 단계가 생기기 전 파이프라인 지도(`kci_maps_perfloor`·`gong_maps_perfloor`)이고,
성적은 그 지도로 잰 것이다. 지도 생성 패키지로 만든 정보관·공대 지도로 바꾸면 성적을 다시 재야 한다.
